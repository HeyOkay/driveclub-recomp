# Accepted working-main source provenance

This profile preserves the accepted main-runtime source foundation and its248-byte settings ABI. It assembles a complete source tree from pinned checkout files plus the differing sources in this overlay. Historical build outputs, external private source directories and captured Sun shader modules are not build inputs.

Sun libraries are standalone authored GLSL. The build generates and validates eight small helper modules: the default portable pair needed by generic transform overloads, plus Standard/High/Ultra variant pairs. Native game shader instructions are recognized by identities and transformed in memory without a native GLSL roundtrip. Native32-tap comparisons/reduction and receiver safety guards remain intact.

Product Standard0 retains native rendering. High1 uses the9216×8192 atlas and accepted Standard-like filtering. Ultra2 uses the intermediate14336×8192 atlas and full near-filter transfer. The original Standard-like texel floor has one shared100m minimum full-strength reach in High/Ultra. The original50m floor remains independently guarded; near radius/reference behavior through50m is bit-exact. Ultra's broader near-softness terms and C0 are unchanged. Native4× reach is retained when already farther. The publisher's fade shape remains; this is not a hard100m cutoff or an extension of caster coverage.

The backend exposes only Standard/High/Ultra, normalizes retired saved or IPC value3 to2, and maps named quick presets below High to Standard, High to High, Ultra to Ultra. Custom preserves its explicit Sun selection. Settings storage and mode physical IDs remain compatible.

Camera source closure retains the accepted authored consumers, allocation order, relocation slots and failure behavior. gforce-native-image.inc and native-group-image.inc record only offsets, lengths, SHA-256 identities and relocation metadata. At runtime the caller's own loaded game image is copied to owned arrays, those arrays are hash-qualified, and exactly those bytes are emitted; no image reread follows qualification. The self-contained SHA implementation adds no DLL dependency. The conversion was checked with4286 CPU cases comparing complete emitted buffers, state, read addresses/sizes and WinAPI event order. It contains none of the eight bulk instruction-body arrays replaced by that conversion. Short signatures and a dormant74-byte observer remain; no claim is made that all native byte patterns were removed.

Game data is obtained through normal user-owned game preparation at launch. Neither the prepared game image nor native instruction-body fixtures are distributed in this source profile. Rear allocation glue is authored assembly regenerated during the build. Runtime finalization precedes automatic backend identity generation; packaged runtime bytes are copied unchanged afterward.

PGO defaults to the included accepted project training profile. Rebuilding with another compiler, disabling or retraining PGO, changing build paths or signing/finalizing bytes can change executable hashes; this profile promises source/build closure, not byte identity with historical executables or a GPU performance result for every toolchain.
